SUMMARY - ANSWER EACH QUESTION FROM THE ITEMS ABOVE
========================================================================
Q1 Authenticator storage & protection:
   Stored in shared_prefs\SecureStore.xml, entry key_v1-SteamGuard_1. Encrypted
   with AES/GCM/NoPadding (tag 128) using Android Keystore alias key_v1 (Expo
   SecureStore, AESEncryptor). KeyGenParameterSpec sets
   setUserAuthenticationRequired(requireAuthentication) but Steam passes FALSE, so
   no PIN/biometric is needed to decrypt. No StrongBox / UnlockedDeviceRequired.
   BiometricPrompt exists in the app but is not applied to Steam Guard. Secret
   field names (shared_secret, identity_secret, revocation_code) appear in the
   bundle as protobuf names only; values stay encrypted in SecureStore.xml.

Q2 Login approval records on device:
   No approve/deny record and no IP/location persisted. The approve/deny UI text
   exists in the bundle (rendered on screen) but the pulls stored nothing.

Q3 Attacker sign-in visible on device:
   Not stored. Only indirect: Steam Guard screen activity timing + Google Maps
   files appearing during Stage A (location likely shown, not saved).

Q4 Traces after an undo:
   Profile edit STEAM01 cached in 03, gone in 04 after undo. Wishlist add/remove
   are server RPCs (C6); TF2 only in the web cache, no local DB record.

Q5 After authenticator moved away:
   Log "Removing local authenticator secrets for <id>..." (01:58:44 UTC).
   SecureStore entry shrank 619 -> 184 chars but the entry REMAINED. Three
   ignored loginRequest notifications just before.

Q6 After logout / clear data:
   Logout: tokens removed from RKStorage (plain SQLite, no encryption - B6/B7),
   BUT WebView steamLoginSecure cookies and the log files remained. "Clearing
   cookies (auth changed)" then "Deleted 0 cookies" (B9/C3). Clear data: both
   internal + external folders emptied. allowBackup=false so no adb-backup path.

Q7 Emulator vs phone (confirm on phone):
   Code identical for both. Device differences to verify on the Xiaomi:
   (a) Keystore hardware-backed vs software (affects whether key_v1 is extractable
   with root); (b) WebView version / black-box fix; (c) whether the WebView is
   debuggable on a release image (B10).

X  Other security notes:
   - A5 network_security_config: cleartextTrafficPermitted=true AND trusts USER
     CAs, no pin-set = no certificate pinning -> traffic can be MITM'd with a user
     CA. Significant finding.
   - A2 allowBackup=false (good). A4 not debuggable (good).
   - JS bridge enabled in the WebView (B11) = attack surface via web content.
